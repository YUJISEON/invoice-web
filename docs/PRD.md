# 노션 연동 견적서 웹 뷰어 MVP PRD

## 🎯 핵심 정보

**목적**: 노션에 작성한 견적서를 클라이언트가 전용 링크로 웹에서 확인하고 PDF로 저장하게 한다.
**사용자**: 노션으로 견적서를 관리하는 1인 사업자/프리랜서(운영자)와, 링크를 받아 로그인 없이 확인하는 클라이언트.

## 🚶 사용자 여정

```
1. [노션 DB] 운영자가 견적서 작성 + 고유 토큰 입력 (앱 외부)
   ↓ 토큰이 포함된 전용 링크를 클라이언트에게 전달

2. [견적서 상세 페이지] 클라이언트가 링크로 접속 (비로그인)
   ↓ 토큰으로 노션 견적서 조회

   [조회 성공]            → 견적서 내용 표시 → 3
   [토큰 없음/형식 불량]  → [오류 안내 페이지] (유효하지 않은 링크)
   [노션 조회 실패/검증 실패] → [오류 안내 페이지] (다시 시도 안내)
   ↓ (만료일 경과 시 견적서 상단에 만료 안내 배너 표시, 조회는 가능)

3. [견적서 상세 페이지] "PDF 다운로드" 버튼 클릭
   ↓ 브라우저 인쇄 대화상자 → PDF로 저장

4. [완료] 클라이언트가 PDF 보관 / 필요 시 같은 링크로 재접속
```

## ⚡ 기능 명세

### 1. MVP 핵심 기능

| ID       | 기능명                | 설명                                                            | MVP 필수 이유                     | 관련 페이지                          |
| -------- | --------------------- | --------------------------------------------------------------- | --------------------------------- | ------------------------------------ |
| **F001** | 토큰 기반 견적서 조회 | 링크의 토큰으로 노션 DB에서 견적서 1건과 품목을 서버에서 조회   | 노션 데이터를 보여주는 핵심 가치  | 견적서 상세 페이지                   |
| **F002** | 견적서 상세 표시      | 견적번호, 발행일, 유효기간, 고객 정보, 품목 표, 합계, 비고 표시 | 클라이언트가 확인하려는 핵심 내용 | 견적서 상세 페이지                   |
| **F003** | PDF 다운로드          | "PDF 다운로드" 버튼으로 인쇄용 레이아웃 적용 후 PDF 저장        | 보관/공유를 위한 기본 니즈        | 견적서 상세 페이지                   |
| **F004** | 접근 오류/만료 안내   | 유효하지 않은 링크, 조회 실패, 유효기간 만료 상태를 구분해 안내 | 고객 노출 화면의 신뢰도 확보      | 견적서 상세 페이지, 오류 안내 페이지 |

### 2. MVP 필수 지원 기능

| ID       | 기능명                | 설명                                                        | MVP 필수 이유                    | 관련 페이지                          |
| -------- | --------------------- | ----------------------------------------------------------- | -------------------------------- | ------------------------------------ |
| **F010** | 노션 데이터 검증/변환 | 노션 응답을 Zod 스키마로 검증하고 화면용 견적서 모델로 변환 | 원본과 일치하는 정확한 표시 보장 | 견적서 상세 페이지, 오류 안내 페이지 |

> 인증은 두지 않습니다. 클라이언트는 비로그인이며 토큰 링크 자체가 접근 수단입니다(F001).

### 3. MVP 이후 기능 (제외)

- 앱 내 견적서 생성/수정, 운영자용 링크·토큰 발급 UI
- 클라이언트 로그인, 견적서 목록/대시보드
- 전자서명, 승인/거절, 온라인 결제
- 다중 통화, 노션 웹훅 실시간 동기화
- 서버 사이드 PDF 렌더링, 열람 여부 추적

## 🗄️ 데이터 모델

원본은 Notion 데이터베이스이며 별도 DB는 두지 않습니다. 아래는 Notion 속성 기준의 논리 모델입니다.

### 견적서 (Notion 견적서 DB의 행)

| 필드                     | 설명                  | 타입/관계 |
| ------------------------ | --------------------- | --------- |
| token                    | 링크 접근용 고유 토큰 | Text      |
| quoteNumber              | 견적번호              | Text      |
| clientName / contactName | 고객사명 / 담당자명   | Text      |
| issuedAt / expiresAt     | 발행일 / 유효기간     | Date      |
| memo                     | 비고 (선택)           | Text      |

### 견적 품목 (견적서에 속한 행)

| 필드      | 설명        | 타입/관계           |
| --------- | ----------- | ------------------- |
| quote     | 소속 견적서 | → 견적서            |
| name      | 품목명      | Title               |
| quantity  | 수량        | Number              |
| unitPrice | 단가        | Number              |
| amount    | 금액        | Number 또는 Formula |

**가정 / 결정 필요**

- 가정: 속성명/타입은 `docs/PRD@old.md`의 가정값이며 실제 노션 템플릿 확인 전까지 미확정입니다.
- 가정: 품목은 별도 Notion DB + Relation(견적서 1 : 품목 N)으로 모델링합니다(`docs/guides/notion-api-database.md` 권장안). 대안(본문 표 블록, JSON 속성)은 결정 필요.
- 결정 필요: 합계(소계/부가세/총액)를 노션 Formula/Rollup으로 둘지, 앱에서 계산할지. 어느 쪽이 원본인지 정해야 "노션과 100% 일치"가 보장됩니다.
- 가정: 단일 통화(KRW), 토큰은 노션에 수동 입력한 충분히 긴 랜덤 문자열.
- 결정 필요: 유효기간 만료 시 금액 노출 여부(현재 가정은 배너만 표시하고 금액은 노출).

## 🛠️ 기술 스택 (최신 버전)

### 🎨 프론트엔드 프레임워크

- **Next.js 15.5.3** (App Router, Turbopack, Server Component) - 서버에서 노션 조회
- **React 19.1** / **TypeScript 5**

### 🎨 스타일링 & UI

- **TailwindCSS v4** (`print:` 변형으로 인쇄 스타일) / **shadcn/ui** / **Lucide React**

### 📝 검증

- **Zod 4** - 노션 응답 검증 (읽기 전용이라 입력 폼은 없으며 React Hook Form은 MVP에서 미사용)

### 🗄️ 데이터 연동

- **Notion API (@notionhq/client v5)** - Integration Token(읽기 권한), `dataSources.query`로 조회, 서버 전용
- 별도 DB 없음 (원본은 Notion DB)

### 📄 PDF 다운로드

- **브라우저 인쇄 (`window.print()` + `@media print`)** 선택: 별도 라이브러리/서버 렌더링 없이 구현 가능하고 한글 폰트 문제가 없어 MVP에 적합(서버 사이드 PDF 생성은 MVP 이후).
