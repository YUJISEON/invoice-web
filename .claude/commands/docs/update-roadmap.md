# Claude 명령어: Update Roadmap

`docs/ROADMAP.md`에서 **구현과 테스트가 모두 끝난 Task만** ✅로 체크하고, 상단 진행 현황을 갱신합니다.

## 사용법

```
/update-roadmap            # 후보 Task를 자동 판정해 제안
/update-roadmap 004        # Task 004 완료 판정
/update-roadmap 004,005    # 여러 Task 동시 판정
```

인자: `$ARGUMENTS`

## 핵심 원칙 (ROADMAP "테스트 공통 규칙")

- **완료 조건**: 구현 + 테스트 체크리스트 전 항목 통과 + `npm run check-all` 통과
- 테스트 전이거나 **실패·미수행 항목이 하나라도 남아 있으면 ✅ 금지**. 대신 ⚠️ 메모로 남긴 항목과 이유를 적습니다
- 사용자가 번호를 지정해도 근거가 부족하면 체크하지 않고 부족한 항목을 알립니다. 체크 여부를 임의로 확정하지 않습니다

## 프로세스

1. `docs/ROADMAP.md`를 읽고 `- **Task XXX:` 줄로 전체 Task 목록과 ✅ 여부를 파악합니다
2. 대상 Task를 정합니다
   - 인자가 있으면 그 번호(3자리, 쉼표 구분)
   - 인자가 없으면 ✅가 없는 Task 중 `tasks/XXX-*.md`가 있는 것을 후보로 제시하고 "어떤 Task를 완료했나요? (예: 004 또는 004,005)"를 묻습니다
3. Task마다 **완료 근거를 확인**합니다 (아래 "완료 판정")
4. 통과한 Task만 체크하고, 통과하지 못한 Task는 이유를 보고합니다
5. 진행 현황·Phase·우선순위 표시를 갱신합니다
6. `npx prettier --write docs/ROADMAP.md`로 표 정렬을 맞추고 변경 내용을 요약합니다

## 완료 판정

각 대상 Task에 대해 다음을 모두 확인합니다.

| 확인 항목                                                                  | 확인 방법                                               |
| -------------------------------------------------------------------------- | ------------------------------------------------------- |
| 테스트 체크리스트(정상/경계/오류/보안·노출/정적 검사)가 전부 통과로 기록됨 | `tasks/XXX-*.md`의 결과 표, ROADMAP Task 본문의 ⚠️ 메모 |
| 미수행·실패 표기가 없음                                                    | `tasks/XXX-*.md`의 **미수행**, ⚠️ 문구 검색             |
| `npm run check-all` 통과                                                   | 직접 실행                                               |
| (해당 시) `npm run build` 통과                                             | Phase 마지막 Task 또는 Task에 명시된 경우 실행          |

- `tasks/XXX-*.md`가 없으면 근거 부족으로 판정하고 작성을 먼저 제안합니다
- "해당 없음"으로 적힌 분류는 이유가 적혀 있으면 통과로 봅니다
- 근거가 부족한 Task는 체크하지 않고, 부족한 항목을 목록으로 보여줍니다

## 업데이트 규칙

### Task 제목

- Before: `- **Task XXX: 작업명** - 우선순위` 또는 `- **Task XXX: 작업명**`
- After: `- **Task XXX: 작업명** ✅ - 완료`
- 이미 ✅가 있는 Task는 건너뜁니다

### Task 하위 항목

- 구현 항목(`테스트 (…)` 블록 밖의 항목)은 앞에 `✅ `를 붙입니다
- `⚠️ 구현 완료, 테스트 …` 같은 미완료 메모는 `✅ 테스트 통과(YYYY-MM-DD): 근거 요약`으로 바꿉니다
- `⚠️ 결정 필요: …`처럼 **아직 결정되지 않은 항목은 ✅로 바꾸지 않고 그대로 둡니다**
- `테스트 (…)` 블록의 하위 항목(정상/경계/오류 …)은 수정하지 않습니다

### 체크하지 못한 Task

- 제목에 ✅를 붙이지 않습니다
- Task 첫 하위 항목으로 `⚠️ 구현 완료, … 미통과/미수행(YYYY-MM-DD): 항목과 이유, 해소 방법`을 추가하거나 기존 메모를 갱신합니다

### 우선순위 표시

- 제목 끝 ` - 우선순위`는 ✅가 없는 Task 중 **번호가 가장 앞선 Task** 하나에만 둡니다
- 방금 완료한 Task의 우선순위 표시는 제거하고 다음 미완료 Task에 붙입니다 (ROADMAP 워크플로우 1)

### Phase 상태

- Phase 안의 모든 Task에 ✅가 있으면 `### Phase N: 제목` → `### Phase N: 제목 ✅`
- 이미 ✅가 있으면 건너뜁니다

### 진행 현황 (ROADMAP 상단 `## 진행 현황`)

```
- 전체: {✅ Task 수} / {전체 Task 수} Task 완료
- 현재 Phase: Phase {✅가 없는 Task가 있는 가장 앞선 Phase 번호}
- 최종 업데이트: {오늘 날짜, YYYY-MM-DD}
```

- 전체 Task 수는 **`- **Task XXX:` 줄 개수\*\*로 계산합니다 (숫자를 고정하지 않음)
- 진행 현황 형식은 위 3줄 목록을 그대로 유지합니다

### 건드리지 않는 곳

- `기능 추적 매트릭스`, `결정 필요 / 가정`, `테스트 데이터 세트` 표
- `현재 코드 상태` 표는 날짜가 오래됐으면 갱신을 제안만 합니다 (임의로 고치지 않음)

## 출력 예시

```
대상: Task 004, 005

✅ Task 004 완료 체크 (근거: tasks/004-quote-view.md 전 항목 통과, check-all 통과)
✅ Task 005 완료 체크 (근거: tasks/005-expired-banner.md, check-all 통과)
⚠️ Task 007 체크 보류: 보안/노출 테스트 1건 미통과 (개발 모드 콘솔에 ZodError 출력)

📊 진행 상황: 6 / 18 Task 완료 (33%)
📍 현재 Phase: Phase 2
📅 최종 업데이트: 2026-11-01
다음 우선순위: Task 007
```

## 주의사항

- Task 번호는 3자리 숫자(001, 002, …)
- 날짜는 YYYY-MM-DD, "오늘 날짜"는 실행 시점의 날짜를 사용
- `docs/ROADMAP.md` 외 파일은 수정하지 않습니다 (`tasks/**`는 읽기 전용)
- 체크 후에도 `npm run check-all`이 통과해야 합니다 (문서 포맷 포함)
