# Task 011: 견적 품목 조회와 합계 교차 검증

관련 기능: F001, F002

## 명세

- `src/lib/notion-mappers.ts`: `mapItemPage`(항목명, 수량, 단가, 금액 formula number. 비어 있는 값은 null로 두어 스키마 검증이 일반 오류로 처리)
- `src/lib/notion.ts`
  - `getQuoteItems(quotePage)`: Items data source를 `Invoices` relation `contains` 견적서 page id로 `dataSources.query`, `page_size` 100, `has_more`/`next_cursor`로 이어서 조회. 품목 DB 설정 오류·미공유는 예외로 전파되어 견적서 일부만 표시하지 않고 전체 오류
  - **정렬: 견적서 쪽 `항목` relation의 연결 순서**(`getItemOrder`). relation이 25개를 넘으면(`has_more`) `pages.properties.retrieve`로 이어서 읽음. 품목이 0~1건이면 순서 조회를 생략
  - `getQuoteByToken`이 품목을 채우고, `sumItemAmounts(items)`가 노션 `총 금액`과 다르면 토큰을 마스킹한 서버 로그(`합계 불일치`)만 남기고 화면은 `total`을 표시

## 정렬 기준을 바꾼 이유 (테스트에서 발견)

최초 구현은 `created_time` 오름차순이었다. 그러나 **노션의 `created_time`은 분 단위로 잘려 저장**되어(품목 30건이 모두 `07:58:00.000Z`) 같은 분에 입력한 품목의 순서가 임의였다. 실제로 화면 순서가 `14, 02, 19, 27, 06…`으로 뒤섞였다. 견적서 쪽 `항목` relation은 연결 순서를 유지하므로 이를 기준으로 정렬하도록 고쳤다(노션 스키마 변경·운영자 추가 작업 없음).

- 한계: 순서는 "품목을 견적서에 연결한 순서"다. 중간에 품목을 끼워 넣으려면 relation에서 해제 후 다시 연결해야 한다. 명시적 순번이 필요해지면 Items DB에 `순번` 숫자 속성을 추가해 그 값으로 정렬하는 방식을 검토한다(MVP 이후)
- 호출 수: 품목 25개 이하 견적서 = 견적서 1 + 품목 1(2회). 25개 초과 = 견적서 1 + 품목 1 + 순서 조회 1(30건 기준 3회). Task 016에서 이 값을 기준으로 점검
