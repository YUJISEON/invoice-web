# Task 015: 보안 점검으로 토큰·키 노출 경로 차단

관련 기능: F001, F004

Task 012·014에서 이미 확인한 비노출 항목(응답·콘솔·서버 로그·`quote.token`·번들)은 재조사하지 않고, 남은 결정 3가지(헤더 강화, 토큰 열거 위험 평가, 변경 후 회귀)에 집중했다.

## 변경

`next.config.ts`의 `headers()`

| 헤더                                        | 변경                                           | 이유                                                                                                                                                                                              |
| ------------------------------------------- | ---------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `Referrer-Policy`                           | `origin-when-cross-origin` → **`no-referrer`** | URL에 접근 토큰이 있으므로 어떤 경우에도 Referer로 전달되지 않게 함. 이 앱에는 외부 링크가 없어 부작용 없음                                                                                       |
| `X-Robots-Tag`                              | **`noindex, nofollow` 추가**                   | 기존 `layout.tsx`의 robots 메타와 이중 적용                                                                                                                                                       |
| `X-XSS-Protection`                          | **제거**                                       | MDN이 deprecated·non-standard로 표시하고 CSP 사용을 권고하며 일부 경우 오히려 취약점을 만들 수 있다고 설명. 이 앱은 입력 폼과 외부 스크립트가 없어 이득이 없음(근거는 MDN만 확인, OWASP는 미확인) |
| `X-Frame-Options`, `X-Content-Type-Options` | 유지                                           |                                                                                                                                                                                                   |

## 토큰 열거 위험 평가

형식이 맞는 무작위 32자 토큰(없는 토큰)을 dev 서버에 요청하고 서버 로그의 `[notion]` 줄로 노션 호출 수를 셌다.

| 시나리오                | 결과                                                                                                                      |
| ----------------------- | ------------------------------------------------------------------------------------------------------------------------- |
| 순차 20회               | 모두 404, 초당 약 2건(총 10.2초), 요청당 평균 508ms·최대 594ms, **요청당 노션 호출 정확히 1회**(20회), 노션 실패 경고 0건 |
| 동시 20회 버스트        | 모두 404, 응답 시간 평균 2.2초·최대 3.1초, 노션 호출 20회, **`rate_limited`(429) 0건**, 실패 경고 0건                     |
| 버스트 직후 정상 견적서 | 200 (1.2초)                                                                                                               |

### 평가

- 형식이 맞는 토큰은 요청마다 노션을 1회 호출한다(형식 불량은 0회). 따라서 요청 속도가 노션 호출 속도가 되며, 노션의 평균 3 req/s 한도를 **지속적으로** 넘기면 429가 발생해 SDK가 재시도(최대 3회)하므로 정상 사용자의 응답이 느려지거나 오류 화면이 나올 수 있다
- 이번 측정에서는 순차 약 2 req/s와 동시 20건 버스트 모두 429가 발생하지 않았다. **지속적인 고속 요청(분 단위)은 측정하지 않았다**(남의 노션 한도를 오래 소진시키는 테스트라 하지 않음)
- 토큰 공간이 192비트라 열거로 유효한 토큰을 맞힐 가능성은 사실상 0이다. 위험은 정보 유출이 아니라 **가용성 저하(레이트 리밋 소진)** 이다
- 판단: MVP에서는 별도 보호를 두지 않는다(링크를 아는 소수 업체가 쓰는 서비스, 노출이 목적이 아닌 비공개 링크). 운영 중 서버 로그에 `[notion] 오류(노션 일시 오류)`가 늘어나면 대응한다

### MVP 이후 후보 (구현하지 않음)

- 요청 제한: Vercel의 요청 제한 기능(플랜별 제공 여부 미확인)이나 미들웨어 기반 IP 제한
- 토큰 사전 필터링: 현재는 형식 검증만 한다(앞 몇 글자 접두사 등 서버 측 사전 검증은 추가 가치가 낮음)
- CSP 헤더 도입(`X-XSS-Protection` 제거의 대체 보호). 입력 폼과 외부 스크립트가 없어 우선순위는 낮음

## 확인하지 못한 것 / 한계

- OWASP 문서는 확인하지 않았다(`X-XSS-Protection` 제거 근거는 MDN 기준)
- 지속적 고속 요청 시 429 발생 임계값은 측정하지 않았다
- dev 서버 로그로 호출 수를 셌다(production은 호출 로그를 남기지 않음). 호출 횟수는 코드 경로가 같아 동일하다
